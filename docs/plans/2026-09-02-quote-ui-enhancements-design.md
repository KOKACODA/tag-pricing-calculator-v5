# 报价界面增强设计说明

日期：2026-09-02

## 目标

在不改变现有报价公式和价格数据的前提下，提高报价结果的可读性，并让纸张材质选择更高效。

## 已确认需求

1. 报价结果中的“成本合计”放大、标红、加粗，使其成为视觉重点。
2. 每个附加工艺和吊绳类型的右上角显示红色数字上标。该数字始终取该选项 `1000` 数量档的初始价格，不随当前报价数量改变；例如“白色方头”显示 `4.5`，“米色棉绳”显示 `9`。
3. 纸张材质下拉框增加搜索预填：输入纸张简称、全称或其中一部分即可模糊筛选，选择结果后沿用原有选纸逻辑。
4. 报价结果中的吊绳费用显示完整明细：`吊绳类型 × 报价数量 = 实际吊绳费用`，并随选择与数量动态更新。

## 设计方案

### 初始价格上标

统一增加“取 1000 档价格”的纯函数，工艺和吊绳复用。只展示数字，不增加货币符号，避免与选项名称争夺视觉空间。若导入配置缺少 1000 档价格，则不显示上标，现有选项仍可正常使用。

### 纸张模糊搜索

搜索框放在每个纸张下拉面板顶部，限定在当前价目表的纸张集合内。搜索采用不区分大小写的分词包含匹配：输入的每个词都能在纸张简称或全称中找到即视为匹配。回车选择第一条可见结果，鼠标点击仍使用现有选择行为；没有结果时显示明确的空状态。

### 报价结果强调与明细

“成本合计”仅改变样式，不修改计算值。吊绳结果使用当前选中的吊绳名称、实际匹配到的报价档数量以及原有计算得到的吊绳费用组成明细；无对应档位价格时保留原有缺价提示，同时仍展示吊绳名称与数量。

## 边界和兼容性

- 不改动价格表、报价公式、利润或税费逻辑。
- 直接报价模式原本不显示吊绳费用，继续保持原行为。
- 搜索只负责筛选和选择，不改变纸张数据结构，也不写入新的持久化字段。
- 所有动态名称继续通过现有 HTML 转义函数输出。

## 验证策略

- 使用 Node 内置测试验证 1000 档初始价格与纸张模糊匹配的纯逻辑。
- 使用 `node --check` 检查脚本语法。
- 启动本地静态服务器，在浏览器中验证上标、搜索选择、成本合计样式和吊绳费用明细。
