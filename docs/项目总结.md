## 一、项目定位

KOKALabel 报价系统是一个面向吊牌/标签（服装吊牌、挂牌、防盗标签等）印刷业务的**报价计算工具**。业务员输入纸张材质、尺寸、数量、工艺、吊绳、邮寄地区等参数，系统自动算出「成本」和「建议售价」。

- **形态**：纯前端单页应用，无后端、无数据库、无框架依赖。
- **运行方式**：双击 `index.html` 即可离线使用（SheetJS 已本地化，导出/导入 Excel 不需要联网）。
- **数据持久化**：全部存在浏览器 `localStorage`（键前缀 `tagPricing_`），刷新不丢失。
- **当前结构**：两个报价表「1楼」（34 张纸）+「3楼」（10 张纸），小组名「1楼小组」「3楼小组」。

## 三、数据模型

### 3.1 三级层级

```
小组 Group（group1「1楼小组」、group2「3楼小组」）
 └─ 报价表 PriceList（priceList1「1楼」= 34 纸；priceList2「3楼」= 10 纸）
     └─ 纸张 Paper（每张纸 = 一个 Excel Sheet）
```

- 一个报价表 = 一个 Excel 文件（多 Sheet）。
- 纸张通过 `priceListId` 字段归属报价表，id 保持稳定（`paper1~paper10` 归 3楼，`paper2_*`/`paper3_*`/`paper4_*` 归 1楼）。

### 3.2 纸张（Paper）字段

| 字段 | 含义 |
|---|---|
| `id` / `name` / `shortName` | 唯一 id、全称（`1楼小组-1：…`）、简称 |
| `discount` | 折扣系数（标准报价模式下纸张乘折扣） |
| `directCoeff` | 直接系数 `{ tiers, max, min }` 三行表格，null 表示无 |
| `batchDirect` | 批量直接报价 `{ maxArea, prices }`，固定价，null 表示无 |
| `specs` | 规格矩阵：`{ code, maxArea, prices }`，code 为面积规格代码（002/003/…/100），prices 为「档位→价格」 |

### 3.3 全局共享配置（不随报价表切换）

- **吊绳 ROPE_CONFIG**：27 种（普通吊绳、各色方头/别针/蜡绳/丝带/涤纶/防拆条/防拆扣等）
- **邮费 SHIPPING_CONFIG**：9 个地区，每地区含 `basePrices`（500/1000/2000/5000/10000 五档）+ `overTierCoeff`（超量系数）
- **客户等级 CUSTOMER_LEVELS**：普通客户 1.2 / 优质客户 1.15 / 大客户 1.1（毛利系数）
- **工艺 CRAFT_CONFIG**：按纸张 id 分组的工艺价格（烫金/UV/鸡眼/凹凸/压凹/击凸/丝印等），36 张纸有工艺

## 四、计价核心逻辑（`calculate()` 在 app.js）

### 4.1 两种计算模式

- **直接系数模式（默认）**：成本 = 纸张 + 工艺；报价 = (纸张价 + 该纸工艺价) × 直接系数。直接系数由纸张表格「最高倍数→普通客户、最低倍数→大客户、中间等差插值」得出。不计吊绳、邮费。
- **标准报价模式**：成本 = 纸张折后价 + 工艺 + 吊绳 + 邮费；报价 = 成本 × 客户等级毛利系数。

### 4.2 面积与规格规则

- **出血面积** = (长 + 3) × (宽 + 3)
- **面积系数**：面积 > 10000 时，系数 = 面积 / 10000（保留两位）
- **强制面积映射**（硬编码）：4000–4999 → `005`；5000–5499 → `055`；**5500–6000 → `006`**（6000 边界强制 006，避免回落到 055 导致价格下降）
- **规格匹配**：非强制区间按 `maxArea >= 面积` 向上取最小规格；`007`/`008` 合并显示
- **批量直接报价**：面积在 `batchDirect.maxArea` 内且档位有价时，直接用固定价（不打折、不乘系数、工艺直接叠加）

### 4.3 邮费三档计算（v8.0 重构）

| 情况 | 条件 | 处理 |
|---|---|---|
| A 固定档 | 数量 = 500/1000/2000/5000/10000 | 直接查 `basePrices` |
| B 超量档 | 数量 > 10000 | 弹对话框输入吊牌重量(kg)，邮费 = 重量 × `overTierCoeff` |
| C 中间档 | 数量为 2500/3000/4000 等无定价档 | 弹对话框手动输入邮费 |

- 重量 / 手动邮费为**会话级缓存**（按地区或地区+档位隔离，刷新后重新询问）。
- 直接系数模式不计邮费。

### 4.4 临时系数、邮费快速修改与联动

- **临时毛利系数**：成本 × 临时系数
- **邮费快速修改**：新成本 = 原成本 − 原邮费 + 新邮费，再 × 客户等级系数；并显示「修改后成本」红字
- **两者同时填写**（v8.1）：合并为 `最终价 = (原成本 − 原邮费 + 新邮费) × 临时系数`，只显示一个合并卡片（临时系数卡片）

### 4.5 邮费快速修改区的显隐策略（v8.6–v8.8 最终定稿）

这是最近几次迭代反复调整的点，最终规则如下：

| 元素 | 受「默认报价」开关控制？ | 备注 |
|---|---|---|
| 默认报价标签 `defaultPriceLabel` | ✅ 是 | |
| 默认客户卡片 `priceCards` | ✅ 是 | |
| 邮费标签 `shippingOverrideLabel` | ✅ 是 | |
| 邮费客户卡片 `shippingOverrideCards` | ✅ 是 | |
| **修改后成本 `shippingOverrideCost`** | ❌ **否（始终显示）** | 用户硬性要求 |

- 即：关闭「默认报价」开关后，除「修改后成本」红字外，其余报价卡片/标签全部隐藏。
- 填了临时系数时（v8.7），邮费标签和客户卡片隐藏（避免与合并卡片重复），但「修改后成本」红字仍显示。

### 4.6 吊牌成本合计（v8.9 新增）

结果区「邮费」行上方新增一行「吊牌成本合计」：
- **公式**：标准模式 = 成本合计 − 邮费（= 纸张+工艺+吊绳，即吊牌本身成本，不含邮费运输）
- 直接系数模式 = 成本合计（本身就不含邮费）
- 缺价时显示「部分缺价」

### 4.7 缺价处理（v8.2 修复）

`costKnown = !hasMissingTier`，纸张/工艺/吊绳/邮费任一缺价即标记「部分缺价」，不生成正式报价。空字符串价格统一为 `null`（v8.5 修复）。

## 八、关键设计决策与坑

1. **三级数据模型**：小组→报价表→纸张，为将来多账号/多报价表预留扩展。
2. **纸张 id 稳定 + 工艺按 id 分组**：工艺（CRAFT_CONFIG）以纸张 id 为 key，纸张 id 不变才能保证工艺不丢。导入新报价表时用唯一 id 避免工艺串扰。
3. **版本迁移机制**：`data.js` 内置多个幂等迁移函数（`migrate*`），旧 localStorage 数据平滑升级。v8.4 起用 `dataVersion` 标记控制一次性覆盖。
4. **空字符串教训（重要）**：Excel 空单元格可能是空字符串 `''` 而非 `null`。`Number('')===0` 会让 `hasExactTier` 把空档位误判为「价格 0」。数据导入/生成时必须统一 `''`→`null`，且判断价格时需 `v !== ""` 防御。
5. **纯函数 + DOM 分层**：`calculate()` 等计算逻辑与 DOM 渲染分离（`const els` 为边界），便于 Node 测试（vm 加载纯函数段）。
6. **zip 自带 .git 的限制**：无法创建带斜杠的分支名（`feature/xxx` 会导致 ref 不落盘、HEAD 悬空），须用不带斜杠的分支名。
7. **显隐策略要一次想完整**：邮费快速修改区的显隐（v8.6→v8.8）反复返工，教训是涉及"哪些元素受开关控制"时先定完整规则再改。
8. **Bash 传 `?v=` 会丢 `v`**：命令行（heredoc）传输含 `?v=` 的字符串时，`?v` 里的 `v` 会被 shell 吞掉，导致用脚本改版本号时漏改资源引用参数；改用编辑器类工具（非 shell）或读文件方式处理才可靠。

## 九、使用与维护要点

- **调价**：只改 `js/data.js` 顶部「价格配置区」（纸张/工艺/吊绳/邮费/客户等级），不改计算与渲染代码。
- **改价后持久化**：就地改价、Excel 导入都会写 localStorage；邮费导入已补持久化（v8.2）。
- **备份**：个人主页 → 数据管理 → 本地备份 / 快照；完整 JSON 导入导出。
- **验证**：`node --check js/app.js js/data.js` 查语法；`node --test tests/*.test.mjs` 跑测试。
- **回退**：`git checkout <tag>`（v7.8.1 ~ v8.9.0 均可回退）。
