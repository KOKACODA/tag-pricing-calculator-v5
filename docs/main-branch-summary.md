## 2. 贯穿全部版本的三条业务铁律（项目灵魂）

这三条规则在 v3.4 确立后，被所有后续版本无条件继承，是理解整个系统行为逻辑的基石：

| 铁律         | 内容                | 技术落实                               |
| ---------- | ----------------- | ---------------------------------- |
| **源数据不可变** | 源 Excel 100% 不被修改 | 解析层只读，全部数据在内存中处理                   |
| **空值不补零**  | 价格表缺失档位不得填入 0     | 解析层空值 → `null`，UI 显示「无该批量定价」占位徽章   |
| **不臆造数据**  | 未匹配档位不得向上取档       | `hasExactTier()` 精确匹配，未命中返回 `null` |

> 这三条铁律的形成背景（决定性的设计决策）：补 0 会把"无此档"误报为"免费"；向上取档会把 500 张的价格错报给 2500 张的客户。详见 [第五部分 · 核心设计决策](#design-decisions)。

**v2.x 计算规则（deploy-process.md 记载，注意与后期差异）**：

- 单张含出血面积 = (长+3) × (宽+3)，出血固定 3mm

- 规格匹配：取 maxArea ≥ 实际面积 的最小规格（向上匹配）

- 档位匹配：**向上取档**（目标档位不存在则取 ≥ 目标的最小档位）——**此逻辑在 v3.4 被废弃**

- 成本 = 纸张折后价 + 工艺费 + 吊绳费 + 邮费；邮费小面积（<2500mm²）享 0.8 折

- 三档报价 = 成本 × 1.30 / 1.15 / 1.05

### 15.2 计算流程（calculate 函数 9 步）

```
输入: sheetCount, tier, sheets[{width,length,sizeType,paperId,craftIds}], ropeId, regionId
│
├─ 1. 参数校验：基础参数非空、sheetCount>0、tier>0、sheets 长度=sheetCount
├─ 2. 查找 rope（ROPE_CONFIG）与 region（SHIPPING_CONFIG），缺失返回 null
│
├─ 3. 逐张纸循环：
│   ├─ 校验 width/length > 0
│   ├─ 查找 paper（PAPER_CONFIG），缺失返回 null
│   ├─ singleArea = calcBleedArea(length, width) = (长+3)×(宽+3)
│   ├─ spec = matchSpec(paper, singleArea)  （向上匹配最小规格）
│   ├─ 纸张原价 = hasExactTier(spec.prices, tier) ? spec.prices[tier] : null
│   ├─ 纸张折后价 = 原价 × paper.discount（null 则标记 hasMissingTier + warning）
│   ├─ 工艺循环：每个工艺独立 hasExactTier，缺价 → null + warning，有价 → craftTotal +=
│   └─ 收集 sheetDetails
│
├─ 4. 吊绳费 = hasExactTier(rope.prices, tier) ? 价格 : null
├─ 5. 邮费 = hasExactTier(region.basePrices, tier) ? 价格 : null
│   └─ 小面积折扣：sheetDetails[0].area < smallAreaThreshold → 邮费 × 0.8
│      （注意：以第一张纸面积判断，多纸张场景为已知技术债）
│
├─ 6. costKnown = 纸张+工艺+吊绳+邮费 全部非 null
│   ├─ 全部有价：cost = paperTotal + craftTotal + ropePrice + shippingPrice
│   └─ 部分缺价：cost = 已知项相加，costIncomplete = true（显示「部分缺价」）
│
├─ 7. pricesByLevel = CUSTOMER_LEVELS.map(等级 → cost × coefficient)
│
└─ 8. 返回 { sheetDetails, tier, paperTotal, paperOriginalTotal, craftTotal,
│          ropePrice, shippingPrice, cost, costIncomplete, hasMissingTier,
│          pricesByLevel, warnings }
```

### 15.3 三个关键匹配策略

| 策略   | 实现       | 说明                                                            |
| ---- | -------- | ------------------------------------------------------------- |
| 规格匹配 | 向上取最小    | 筛选 maxArea ≥ 实际面积 的规格，取面积最小者；007/008 合并显示；>10000 报「请与上级联系」    |
| 档位匹配 | 精确匹配     | `hasExactTier()` 直接查 prices\[tier]，未命中 null，**不向上取档**（v3.4 起） |
| 面积计算 | 固定出血 3mm | 单张/展开均按 (长+3)×(宽+3)（未区分 sizeType，为已知简化）                       |

### 15.4 成本公式（正式定义）

```
单张含出血面积   = (长 + 3) × (宽 + 3)
纸张折后价       = Σ [规格原价 × 纸张折扣系数]        （原价 = spec.prices[tier]）
工艺总费用       = Σ [工艺价格]                       （各工艺独立按 tier 精确匹配）
吊绳费用         = rope.prices[tier]                 （rope0 全档位为 0）
邮费             = region.basePrices[tier] × (面积 < 2500 ? 0.8 : 1)
成本合计         = 纸张折后价 + 工艺总费用 + 吊绳费用 + 邮费
建议报价         = 成本合计 × 客户等级系数（1.30 / 1.15 / 1.05）
```

### 15.5 缺价处理机制（铁律落地）

```
价格对象 ── hasExactTier() ── 命中 → 数值参与累加
                    │
                    └── 未命中 → null
                        ├─ hasMissingTier = true
                        ├─ warnings.push(`「X」无 Y 张批量定价`)
                        ├─ 成本 costIncomplete = true → UI 显示「部分缺价」
                        └─ UI 单元格显示 .price-missing 徽章「无该批量定价」
```

### 15.6 完整示例：350铜版纸 500 张

**输入**：paper1（折扣 1.00），宽 55mm × 长 30mm，500 张，广东省内，不加吊绳。

```
① 面积：singleArea = (55+3) × (30+3) = 58 × 33 = 1914 mm²
② 规格：maxArea ≥ 1914 的最小规格 → code "002"（maxArea 1999）
③ 纸张原价：spec.prices[500] = 20 元
④ 纸张折后价：20 × 1.00 = 20 元
⑤ 工艺：paper1 无工艺 → 0
⑥ 吊绳：rope0 → 0
⑦ 邮费：region1.basePrices[500] = 12；面积 1914 < 2500 → 12 × 0.8 = 9.6
⑧ 成本：20 + 0 + 0 + 9.6 = 29.6
⑨ 报价：普通客户 29.6×1.30 = 38.48
       优质客户 29.6×1.15 = 34.04
       大客户   29.6×1.05 = 31.08
```

### 15.7 边界条件推演

| 场景                 | 处理                 | 结果              |
| ------------------ | ------------------ | --------------- |
| 面积 > 10000 mm²     | matchSpec 返回 error | 返回「请与上级联系」，终止计算 |
| 面积无规格覆盖            | 无候选                | 返回「未找到匹配规格」     |
| 档位缺价               | hasExactTier false | 纸张费 null + 警告   |
| 面积 < 2500          | 邮费 × 0.8           | 小面积优惠           |
| 尺寸类型 single/spread | 统一按输入长宽计算          | 面积相同（简化实现）      |
| 吊绳 rope0           | 全档位 0              | 免费，不产生缺价警告      |

### 15.8 多纸张成本语义

```
paperTotal（折后合计）= Σ 每张纸折后价（各自独立匹配规格/档位）
paperOriginalTotal（折扣前合计）= Σ 每张纸原价
工艺费用 = Σ 所有纸张选中的工艺价格（工艺按纸张绑定）
吊绳/邮费 = 单次（不随纸张数量翻倍）
```

**语义澄清**：纸张数量（sheetCount）指**报价单包含几种纸**，而非每种纸的张数；总批量档位（tier）适用于全部纸张；吊绳/邮费按整体计算一次。

## 17. Excel 导入导出流程

### 17.1 导出/模板流程

```
downloadPaperTemplate()
  └─ 内置 TEMPLATE_ROWS（9 张表，1:1 还原源 Excel）
      ├─ meta: 所属小组 / 总报价表 / 全称 / 简称 / 折扣系数 / 备注
      ├─ codeHeader: 代码 + 最大含出血面积 + 该纸档位表头
      ├─ codeRows: 规格数据
      └─ craftRows: 工艺名称 + 档位价格（无工艺则省略）
  └─ XLSX.writeFile("KOKALabel1号报价表_日期.xlsx")

exportPaperExcel()
  └─ 遍历 PAPER_CONFIG → paperToSheetRows(paper)
      ├─ 规格档位 ∪ 工艺档位并集排序 = tierKeys（列宽对齐关键）
      ├─ 缺值留 ""（与源数据一致，不写 0）
```

### 17.2 导入流程

```
parsePaperExcel(arrayBuffer)
  ├─ XLSX.read → 遍历 SheetNames
  ├─ 表头区（前 8 行）标签匹配
  ├─ 定位规格标题行「代码」+「最大含出血面积」
  ├─ 档位表头：第 3 列起纯数字且 >0 → tierKeys
  ├─ 规格数据行：遇「工艺名称」break；空价格 → null
  ├─ 工艺区：定位「工艺名称」标题 → 逐行读价格
  ├─ paper id 复用：按简称匹配 DEFAULT_PAPER_CONFIG 保留原 id
  └─ 返回 { papers, crafts, errors }

importPaperExcel(file)
  ├─ FileReader 读取 → parsePaperExcel
  ├─ PAPER_CONFIG = 导入数据；CRAFT_CONFIG = 默认 ∪ 导入工艺
  └─ rebuildPaperUI() 重建界面
```

### 17.3 解析容错规则汇总

| 场景                           | 处理               |

# 第五部分 · 设计决策、技术债与演进方法论

## <a name="design-decisions"></a> 21. 核心设计决策（铁律的形成）

| 决策       | 触发背景                      | 技术实现                              |
| -------- | ------------------------- | --------------------------------- |
| 源数据不可变   | 修改 Excel 有误改风险，且无法追溯      | 解析只读，内存操作                         |
| 空值不补 0   | 补 0 会把「无此档」误报为「免费」        | 空值 → `null` → UI 占位徽章             |
| 精确档位匹配   | 向上取档会把 500 张价错报给 2500 张客户 | `hasExactTier()` 只认精确档位           |
| 规格向上匹配   | 印刷品规格必须物理覆盖成品面积           | `matchSpec()` 取 maxArea ≥ 面积的最小规格 |
| 固定出血 3mm | 印刷裁切需出血，行业标准 3mm          | `calcBleedArea()` 统一 (长+3)×(宽+3)  |

### 21.1 系统原理

**业务原理**：吊牌制造的成本构成是**阶梯式**的——同一规格产品，批量越大单张成本越低；不同纸张/工艺/配送地区各有独立价格阶梯。Excel 报价表将这一阶梯固化为「规格代码 × 批量档位」的二维价格矩阵。系统核心原理，就是把**矩阵查询 + 四要素求和 + 毛利换算**三步人工计算自动化。

**技术原理**：

| 原理               | 说明                                             |
| ---------------- | ---------------------------------------------- |
| 单文件架构            | 全部逻辑打包进一个 HTML，浏览器打开即运行，无服务器/构建/数据库依赖          |
| CDN 数据交换         | SheetJS 在浏览器端解析/生成 xlsx，数据不离开用户设备              |
| localStorage 持久化 | 浏览器本地存储客户配置                                    |
| 静态部署             | Cloudflare Pages 只做静态托管，push 触发构建              |
| 降级机制             | `typeof XLSX === "undefined"` 检测 CDN 失败，给出可读错误 |

## 29. 关键术语速查

| 术语              | 含义                                              |
| --------------- | ----------------------------------------------- |
| 出血面积            | `(长 + 3) × (宽 + 3)`                             |
| 面积系数            | 面积 > 10000 时 = 面积 / 10000（保留两位）                 |
| 强制面积映射          | 4000-4999→`005`，5000-5499→`055`，5500-6000→`006` |
| 直接系数            | 每 Sheet「最高/最低倍数」三行，最高→普通客户、最低→大客户、中间等差插值        |
| 标准报价            | (纸张折后价 + 工艺 + 吊绳 + 邮费) × 客户等级毛利系数               |
| 批量直接报价          | 面积在最大面积内且档位有价时按固定价（不打折不乘系数）                     |
| 临时毛利系数 / 邮费快速修改 | 报价结果区两个「快速重算」输入                                 |
| 三条铁律            | 源数据不可变、空值不补 0、不臆造数据                             |
| EPHEMERAL\_KEYS | 测试期"启动即清除"的临时存储键集合                              |
