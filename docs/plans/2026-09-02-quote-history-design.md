# 默认报价开关与报价历史设计说明

日期：2026-09-02

## 目标

为标准报价增加可持久化的默认报价显隐控制，并把现有“报价历史”占位功能升级为可实际使用的本地报价档案：支持客户名称、订单备注、结果快照、查看、删除和重新载入参数。

## 已确认需求

1. “参数输入”标题旁增加默认报价显示开关。
2. 开关只影响标准报价中的普通客户、优质客户和大客户默认报价板块，不改变任何计算值。
3. 开关状态写入本地存储，刷新或重新打开页面后继续使用上次状态。
4. 报价结果末尾可以手动保存当前报价。
5. 保存时可填写客户名称和订单备注；客户名称为空时自动生成“编号＋时间”名称。
6. 报价历史支持查看原始快照、删除记录、重新载入当时的输入参数。

## 方案比较与选择

### 方案一：只保存列表摘要

占用空间最少，但无法查看纸张、工艺和客户等级价格的完整细节，也无法可靠恢复输入，不满足回头核价的目的。

### 方案二：只保存输入参数

可以重新计算，但后续价格表调整后无法还原保存当时的报价结果，历史记录不具备审计价值。

### 方案三：同时保存输入参数与结果快照（采用）

历史查看读取保存时的结果快照，因此以后调价不会改变旧记录；“重新载入参数”只恢复输入，并使用当前价格重新计算。该方案占用少量额外本地空间，但行为最清晰，也同时满足复查和二次报价。

## 数据结构

报价记录继续使用现有 `tagPricing_history` 本地存储键，新增记录使用版本化结构：

```text
id / schemaVersion / recordNo / title / customerName / note / createdAt
mode / priceList
inputs: 报价表、模式、档位、纸张数量、每张纸参数、吊绳、地区
snapshot: 保存时的完整计算结果、吊绳名称、地区名称
```

记录编号格式为 `BJ-YYYYMMDD-HHMMSS`。客户名称为空时，记录标题直接使用该编号；有客户名称时，列表优先显示客户名称，同时保留编号。

## 界面设计

显隐开关放入现有标题控制组，使用可访问的 `role="switch"` 按钮，视觉上保持蓝白色工具型界面。开关在直接系数模式下仍显示当前偏好，但只在切换到标准报价后生效。

报价结果末尾增加紧凑的保存面板，包含客户名称、订单备注、“保存报价”和“查看记录”。原个人主页中的“报价历史”标签页改为正式记录表格，提供查看、载入参数和删除操作；查看详情使用模态对话框展示保存时的输入与价格快照。

## 参数重新载入

载入时恢复报价表、计算模式、批量档位、纸张数量、各纸张材质/尺寸/工艺/手动代码、吊绳和地区，然后按当前价格重新计算。若原报价表或纸张已被删除，则不修改当前参数，并提示用户只能查看历史快照。

## 错误处理与兼容性

- 没有有效计算结果时拒绝保存。
- 本地存储写入后立即校验记录是否存在，存储空间不足时提示保存失败。
- 所有客户名称、备注和动态名称继续经过 HTML 转义。
- 旧版占位历史记录仍可显示和删除，但因为没有完整参数，只禁用“载入参数”。
- 本地备份原本已经包含 `history`，继续兼容，无需增加新的导出入口。

## 验证策略

- Node 测试验证显隐规则、记录编号、客户名回退和快照深拷贝。
- 语法检查验证 `js/app.js` 和 `js/data.js`。
- 浏览器验证刷新后的开关状态、保存、详情查看、参数重载和删除全流程，并检查控制台无错误。
