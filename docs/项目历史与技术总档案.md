## 二、项目总览

### 2.1 项目定位

KOKALabel 报价系统是一款面向吊牌、标签、不干胶印刷业务的报价计算工具。业务员输入纸张材质、尺寸、数量、工艺、吊绳、邮寄地区等参数，系统自动计算「成本」与「建议售价」，并按客户等级输出不同口径的报价。

- **形态**：纯前端单页应用，无后端、无数据库、无框架依赖。
- **运行方式**：双击 `index.html` 即可离线使用，SheetJS 已本地化，导出与导入 Excel 无需联网。
- **数据持久化**：全部保存在浏览器 `localStorage`（键前缀 `tagPricing_`），刷新不丢失。
- **当前数据**：两个报价表「1楼」（28 个报价组）+「3楼」（10 张纸），小组名为「1楼小组」「3楼小组」。

### 2.2 核心业务逻辑概览

报价围绕四个要素展开——纸张、工艺、吊绳、邮费——再加上客户等级毛利系数，构成成本与售价。系统支持三种计价路径：

1. 直接系数模式（默认）：成本 = 纸张 + 工艺；报价 =（纸张 + 工艺）× 直接系数。
2. 标准报价模式：成本 = 纸张折后价 + 工艺 + 吊绳 + 邮费；报价 = 成本 × 客户等级毛利系数。
3. 批量直接报价：面积在阈值内且有固定价时，直接用固定价，不打折、不乘系数。

### 2.3 技术栈与部署

| 项 | 内容 |
|---|---|
| 结构与交互 | 原生 HTML + CSS + JavaScript（ES6+），无框架 |
| 数据 | 浏览器 `localStorage`，键前缀 `tagPricing_` |
| Excel 读写 | SheetJS（`xlsx.full.min.js`）本地化于 `js/vendor/` |
| 测试 | Node 内置 `node:test`，通过 `vm` 加载纯函数段 |
| 部署 | GitHub 仓库 + Cloudflare Pages（`wrangler pages deploy` 直传） |
| 线上地址 | https://tag-pricing-calculator-v5.pages.dev |

## 三、开发历史

项目的历史跨越三条独立的演进脉络，最终收敛到当前 `v8` 分支（v9.4.2）。理解整个开发历史的关键，是先区分这三条脉络的时间顺序与 git 关系。

### 3.1 起源与前史（2026-07-28 至 08-01）

项目最早叫「海洋吊牌报价系统」，其第一形态是「报价查询系统」——把依赖 Excel 手动查价格表的人工流程，转化为可在线查询的 Web 工具。2026-07-28 首版上线，提供 10 种纸张价格表的查询，含搜索、排序、高亮、分页与毛利计算。

随后在 08-01，业务需求从「查价格」升级为「算价格」，独立出「报价计算器」项目。第一版 `tag-pricing-calculator.html` 引入了 PAPER / ROPE / SHIPPING / CUSTOMER_LEVELS 四类配置与 `calculate()` 计算逻辑，v2.0 将吊绳价格按 Excel 更新为 26 种。

这个时期的系统是单文件 HTML，无版本号管理，数据硬编码在脚本中。

### 3.2 早期单文件时代（v1.0 至 v4.3，2026-08-01 至 08-06）

这是从「计算器」到「成熟报价工具」的关键成长期，可细分为四个阶段：

**Excel 化重构（v2.4 → v3.x）**：v3.0 引入 SheetJS，把报价数据从硬编码转为可导入 Excel 配置；v3.4 是一个里程碑，确立了贯穿项目全程的三条业务铁律——源数据不可变、空值不补零、不臆造数据。这三条规则在后续所有版本中被无条件继承。

**质量修复（v4.0）**：删除早期开发中混入的 TRAE CSS 污染 1,213 行（体积 -32%），修复小数位硬编码、存储型 XSS、快照不完整、事件重复绑定等问题，并补充 `noindex` 与 `robots.txt`。

**架构与品牌化（v4.2 → v4.3）**：v4.2 完成全端响应式适配；v4.2.1 将「海洋吊牌厂」统一更名为 KOKALabel；v4.3 建立三级数据架构（小组 → 报价表 → 纸张），为后续多报价表扩展打底。

这一时期的版本历史详见 `docs/main-branch-summary.md`，其完整表见本文档 3.6 节。

### 3.7 三条业务铁律（项目灵魂）

三条铁律于 v3.4 确立，被所有后续版本无条件继承，是理解系统行为逻辑的基石：

1. **源数据不可变**：源 Excel 100% 不被修改，解析层只读，全部数据在内存中处理。
2. **空值不补零**：价格表缺失档位不得填入 0，解析层空值转 `null`，界面显示「无该批量定价」占位徽章。
3. **不臆造数据**：未匹配档位不得向上取档，`hasExactTier()` 精确匹配，未命中返回 `null`。

其形成背景是两条决定性的教训：补 0 会把「无此档」误报为「免费」；向上取档会把 500 张的价格错报给 2500 张的客户。

## 四、技术架构

### 4.1 技术栈与运行形态

项目坚持零依赖、零后端，用最朴素的组合实现完整业务逻辑，换取部署简单与离线可用：

- **结构**：单个 `index.html`，承载三个页面（智能报价计算器、报价表组查询、个人主页）与全部对话框、toast。
- **样式**：单个 `css/style.css`，CSS 变量主题，蓝白工具型界面，响应式适配桌面与移动端。
- **逻辑**：单个 `js/app.js`，集中计算、渲染、交互、导入导出。
- **数据**：单个 `js/data.js`，集中价格配置、存储封装与版本迁移。
- **依赖**：唯一第三方库 SheetJS，本地化于 `js/vendor/xlsx.full.min.js`，脱离 CDN 与网络。

这一设计的直接收益是：应用可以双击 `index.html` 以 `file://` 协议离线运行，同时满足严格的内容安全策略（CSP `script-src 'self'`）。

### 4.2 文件结构与职责

| 文件 | 行数 | 职责 |
|---|---|---|
| `index.html` | 约 1,137 | HTML 骨架、CSP、三页面结构、对话框 |
| `css/style.css` | 约 3,166 | 全部样式，CSS 变量主题 |
| `js/app.js` | 约 4,993 | 计算、渲染、交互、导入导出、初始化 |
| `js/data.js` | 约 9,529 | 价格数据、存储、版本迁移 |
| `js/vendor/xlsx.full.min.js` | 内置库 | SheetJS，Excel 读写 |
| `tests/*.test.mjs` | 五文件 | Node 单元测试，vm 加载纯函数段 |
| `_headers` / `robots.txt` | — | Cloudflare 安全头 / 屏蔽搜索引擎收录 |

`js/data.js` 的九成内容是静态价格数据，其中 `DEFAULT_PAPER_CONFIG`（纸张/报价组）、`DEFAULT_CRAFT_CONFIG`（工艺）、`DEFAULT_ROPE_CONFIG`（吊绳）、`SHIPPING_CONFIG`（邮费）、`DEFAULT_CUSTOMER_LEVELS`（客户等级）是唯一的数据维护区。修改价格只动这里，不改计算与渲染代码。

### 4.3 三级数据模型

数据组织为三级层级，为多报价表、多账号扩展预留空间：

```
小组 Group（group1「1楼小组」、group2「3楼小组」）
 └─ 报价表 PriceList（priceList1「1楼」、priceList2「3楼」）
     └─ 纸张 Paper（每张纸 = 一个 Excel Sheet）
```

一个报价表对应一个 Excel 文件（多 Sheet），每张纸对应一个 Sheet。纸张通过 `priceListId` 字段归属报价表。当前数据为：1楼 28 个报价组（paper2_1 ~ paper2_28），3楼 10 张纸（paper1 ~ paper10）。

### 4.4 纸张字段结构

纸张（报价组）的关键字段：

| 字段 | 含义 |
|---|---|
| `id` / `name` / `shortName` | 唯一 id、全称、简称 |
| `discount` | 折扣系数（仅标准报价模式生效） |
| `directCoeff` | 直接系数三行表 `{tiers, max, min}`，null 表示无 |
| `batchDirect` | 批量直接报价 `{maxArea, prices}` 固定价，null 表示无 |
| `specs` | 规格矩阵 `{code, maxArea, prices}`，code 为面积规格代码 |

### 4.5 全局共享配置（不随报价表切换）

- **吊绳 `ROPE_CONFIG`**：27 种（普通吊绳、各色方头/别针/蜡绳/丝带/涤纶/防拆条/防拆扣等）。
- **邮费 `SHIPPING_CONFIG`**：9 个地区，每地区含 `basePrices`（500/1000/2000/5000/10000 五档）+ `overTierCoeff`（超量系数）。
- **客户等级 `CUSTOMER_LEVELS`**：普通客户 1.2 / 优质客户 1.15 / 大客户 1.1（毛利系数）。
- **工艺 `CRAFT_CONFIG`**：按纸张 id 分组的工艺价格（烫金/UV/鸡眼/凹凸/击凸/丝印等）。

### 4.6 计价核心逻辑

三种计价路径的成本与报价构成：

| 模式 | 成本 | 报价 |
|---|---|---|
| 直接系数（默认） | 纸张 + 工艺 |（纸张 + 工艺）× 直接系数 |
| 标准报价 | 纸张折后价 + 工艺 + 吊绳 + 邮费 | 成本 × 客户等级毛利系数 |
| 批量直接报价 | 固定价 + 工艺（面积 ≤ `batchDirect.maxArea` 且档位有价） | 固定价，不打折不乘系数 |

**面积与规格规则**：

- 出血面积 =（长 + 3）×（宽 + 3），出血固定 3mm。
- 面积系数：面积 > 10000 时，系数 = 面积 / 10000，保留两位。
- 强制面积映射（硬编码）：4000–4999 → `005`；5000–5499 → `055`；5500–6000 → `006`（6000 边界强制 006，避免回落到 055 导致价格下降）。
- 规格匹配：非强制区间按 `maxArea >= 面积` 向上取最小规格；`007`/`008` 合并显示。

**邮费三档计算（v8.0 重构）**：

| 情况 | 条件 | 处理 |
|---|---|---|
| 固定档 | 数量 = 500/1000/2000/5000/10000 | 直接查 `basePrices` |
| 超量档 | 数量 > 10000 | 弹对话框输入吊牌重量（kg），邮费 = 重量 × `overTierCoeff` |
| 中间档 | 数量为 2500/3000/4000 等无定价档 | 弹对话框手动输入邮费 |

重量与手动邮费为会话级缓存，刷新后重新询问。直接系数模式不计邮费。

**临时系数与邮费快速修改**：

- 临时毛利系数：成本 × 临时系数。
- 邮费快速修改：新成本 = 原成本 − 原邮费 + 新邮费，再 × 客户等级系数。
- 两者同时填写时合并为 `最终价 =（原成本 − 原邮费 + 新邮费）× 临时系数`，只显示一个合并卡片。

**邮费快速修改区显隐规则（v8.6 至 v8.8 最终定稿）**：「默认报价」开关控制默认报价标签、默认客户卡片、邮费标签、邮费客户卡片；「修改后成本」红字始终显示，不受开关控制。

**吊牌成本合计（v8.9 新增）**：结果区「邮费」行上方新增一行。标准模式 = 成本合计 − 邮费（= 纸张 + 工艺 + 吊绳，不含邮费运输）；直接系数模式 = 成本合计；缺价时显示「部分缺价」。

**缺价处理（v8.2 修复）**：`costKnown = !hasMissingTier`，纸张/工艺/吊绳/邮费任一缺价即标记「部分缺价」，不生成正式报价；空字符串价格统一为 `null`。

### 4.7 数据持久化与版本迁移

全部数据持久化在浏览器 `localStorage`，键前缀 `tagPricing_`。核心键包括纸张配置、工艺、吊绳、邮费、客户等级、公司信息、个人偏好、报价表组、报价历史（`history`）、本地快照（`snapshots`）。

`data.js` 内置多个幂等迁移函数（`migrate*`），配合 `dataVersion` 标记，让旧版用户的 localStorage 数据在首次加载时平滑升级到新版结构，无需手动重置。典型迁移包括 v8.4 的纠正数据覆盖、v9.0 的 1楼报价表替换（仅替换 1楼，保留 3楼含用户自定义改价）。

### 4.8 安全设计

- **XSS 防护**：`escapeHtml` 补齐双引号/单引号转义，所有动态内容（报价表名、工艺名、导入文件名、错误信息等）转义后再拼入 HTML。
- **导入校验**：价格拒绝负数与 `NaN`/`Infinity`，规格档位去重并升序；五个导入入口统一 50MB 上限；备份 JSON 全结构深校验。
- **公式注入防护**：导出 Excel 的名称/代码单元格经 `safeExcelText` 处理，`=`/`+`/`-`/`@` 开头自动加单引号转文本。
- **数据防篡改**：导出时经 `signExport` 对数据体计算 SHA-256 写入 `meta.integrity`，导入时重算比对，篡改即阻断。
- **前端口令门**：启动时校验 `sessionStorage` 解锁状态，未解锁先要求口令（SHA-256 比对），解锁仅写 sessionStorage（关页失效）。
- **响应头**：`_headers` 配置 HSTS 与完整 CSP；HTML 头部另设 `X-Frame-Options`、`noindex`。

### 4.9 测试体系

测试用 Node 内置 `node:test`，通过 `vm` 模块加载 `js/data.js` 与 `js/app.js` 的纯函数段（以 `renderHistory` 为边界截断），隔离 DOM 依赖。五个测试文件：

| `tests/quote-history.test.mjs` | 报价历史的保存、载入、删除 |
| `tests/security-hardening.test.mjs` | XSS 转义、导入校验、Excel 公式注入 |
| `tests/stats.test.mjs` | 统计聚合、尺寸解析、利润分桶、条形图渲染 |
| `tests/ui-enhancements.test.mjs` | UI 增强回归 |

验证命令：`node --check js/app.js js/data.js` 做语法检查，`node --test tests/*.test.mjs` 跑全量单测。

## 六、关键设计决策与技术债

### 6.1 设计决策

1. **三级数据模型**：小组 → 报价表 → 纸张，为多账号、多报价表扩展预留空间。
2. **纸张 id 稳定 + 工艺按 id 分组**：工艺以纸张 id 为 key，纸张 id 不变才能保证工艺不丢；导入新报价表时用唯一 id 避免工艺串扰。
3. **版本迁移机制**：`data.js` 内置幂等 `migrate*` 函数，配合 `dataVersion` 控制一次性覆盖，旧数据平滑升级。
4. **纯函数与 DOM 分层**：`calculate()` 等计算逻辑与 DOM 渲染分离（`const els` 为边界），便于 Node 测试。
5. **零后端取舍**：为离线与部署简单放弃后端，数据只存本机 localStorage，也因此引出「不上传云端」的设计原则。

### 6.2 技术债与教训

1. **空字符串教训**：Excel 空单元格可能是空字符串 `''` 而非 `null`，`Number('') === 0` 会让 `hasExactTier` 把空档位误判为「价格 0」。数据导入/生成时必须统一 `''` → `null`，判断价格时需 `v !== ""` 防御。v8.5 曾一次性修复 106 处该问题。
2. **显隐策略要一次想完整**：邮费快速修改区的显隐在 v8.6 至 v8.8 反复返工，教训是涉及「哪些元素受开关控制」时先定完整规则再改。
3. **zip 自带 .git 的限制**：无法创建带斜杠的分支名（`feature/xxx` 会导致 ref 不落盘），须用不带斜杠的分支名。
4. **Bash 传 `?v=` 会丢 `v`**：用脚本改版本号时 `?v` 里的 `v` 会被 shell 吞掉，导致漏改资源引用参数；应改用编辑器类工具读取文件方式处理。
5. **直接系数中间档浮点舍入**：如 1.275 显示为 1.27（浮点误差），已知未处理，不影响主流程。
6. **双 git 谱系的历史包袱**：v8 谱系与旧 main 谱系无共同提交，长期并存导致 `main` 分支长期停留在旧 v7.10；v9.4.2 已通过 force 同步将其收敛。

## 十一、版本演进方法论反思

回看从 2026-07-28 至今约四十天的演进，可提炼出几条可复用的方法论：

1. **先立规矩再写功能**：三条业务铁律（源数据不可变、空值不补零、不臆造数据）在 v3.4 确立后成为所有后续功能的底线，避免了大量「补 0 误报免费」「向上取档报错价」一类业务事故。
2. **数据迁移要幂等**：`migrate*` 函数配合 `dataVersion`，让每次数据结构变更都能对所有老用户平滑升级，而非要求手动重置。
3. **计算与渲染分层**：纯函数 `calculate()` 与 DOM 渲染分离，使核心逻辑可被 Node 单测覆盖，这是项目能持续扩充测试的前提。
4. **体积治理是持续动作**：从 v4.0 的 CSS 污染清理，到 v8 的 SheetJS 本地化，项目始终在「功能增长」与「体积可控」之间做取舍。
5. **文档随代码同步演进**：从早期的 `AGENT-INSTRUCTIONS.md` 到 `AGENTS.md`、`HANDOFF`、本文档，接手成本被逐步压缩，是跨设备、跨 agent 协作能持续的隐性基础设施。
