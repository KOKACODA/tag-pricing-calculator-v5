
### 2.3 吊绳价格换算公式

Excel 原始数据单位为 **元/1000张**：

```
档位价格 = (元/1000张) × 档位数量 ÷ 1000
```

示例：普通吊绳 10 元/1000张 → 500张=5.0、1000张=10.0、5000张=50.0。

### 3.2 计算流程（calculate 函数 9 步）

```
输入: sheetCount, tier, sheets[{width,length,sizeType,paperId,craftIds}], ropeId, regionId
│
├─ 1. 参数校验：基础参数非空、sheetCount>0、tier>0、sheets 数组长度=sheetCount
├─ 2. 查找 rope（ROPE_CONFIG）与 region（SHIPPING_CONFIG），缺失返回 null
│
├─ 3. 逐张纸循环：
│   ├─ 校验 width/length > 0
│   ├─ 查找 paper（PAPER_CONFIG），缺失返回 null
│   ├─ singleArea = calcBleedArea(length, width) = (长+3)×(宽+3)
│   ├─ spec = matchSpec(paper, singleArea)  （向上匹配最小规格；>10000 报错）
│   ├─ 纸张原价 = hasExactTier(spec.prices, tier) ? spec.prices[tier] : null
│   ├─ 纸张折后价 = 原价 × paper.discount（null 则标记 hasMissingTier + warning）
│   ├─ 工艺循环：每个工艺独立检查 hasExactTier，缺价 → null + warning，有价 → craftTotal +=
│   └─ 收集 sheetDetails（纸张名/尺寸/面积/代码/单价/工艺明细）
│
├─ 4. 吊绳费 = hasExactTier(rope.prices, tier) ? 价格 : null（缺价 + warning）
├─ 5. 邮费 = hasExactTier(region.basePrices, tier) ? 价格 : null
│   └─ 小面积折扣：sheetDetails[0].area < smallAreaThreshold → 邮费 × 0.8
│      （注意：以第一张纸面积判断，多纸张场景为已知技术债）
│
├─ 6. costKnown = 纸张+工艺+吊绳+邮费 全部非 null
│   ├─ 全部有价：cost = paperTotal + craftTotal + ropePrice + shippingPrice
│   └─ 部分缺价：cost = 已知项相加，costIncomplete = true（UI 显示「部分缺价」）
│
├─ 7. pricesByLevel = CUSTOMER_LEVELS.map(等级 → cost × coefficient)
│
└─ 8. 返回 { sheetDetails, tier, paperTotal, paperOriginalTotal, craftTotal,
│          ropePrice, shippingPrice, cost, costIncomplete, hasMissingTier,
│          pricesByLevel, warnings }
```

### 3.3 三个关键匹配策略

| 策略 | 实现 | 说明 |
|------|------|------|
| 规格匹配 | **向上取最小** | 筛选 maxArea ≥ 实际面积 的规格，取面积最小者；007/008 合并显示为「007/008」；面积 >10000 报「请与上级联系」 |
| 档位匹配 | **精确匹配** | `hasExactTier()` 直接查 prices[tier]，未命中返回 null，**不做向上取档**（v3.4 起） |
| 面积计算 | **固定出血 3mm** | 单张/展开均按 (长+3)×(宽+3) 计算（当前实现未区分 sizeType，为已知简化） |

### 3.4 成本公式（正式定义）

```
单张含出血面积   = (长 + 3) × (宽 + 3)
纸张折后价       = Σ [规格原价 × 纸张折扣系数]        （原价 = spec.prices[tier]）
工艺总费用       = Σ [工艺价格]                       （各工艺独立按 tier 精确匹配）
吊绳费用         = rope.prices[tier]                 （rope0 全档位为 0）
邮费             = region.basePrices[tier] × (面积 < 2500 ? 0.8 : 1)
成本合计         = 纸张折后价 + 工艺总费用 + 吊绳费用 + 邮费
建议报价         = 成本合计 × 客户等级系数（1.30 / 1.15 / 1.05）
```

### 3.5 缺价处理机制（铁律落地）

```
价格对象 ── hasExactTier() ── 命中 → 数值参与累加
                    │
                    └── 未命中 → null
                        ├─ hasMissingTier = true
                        ├─ warnings.push(`「X」无 Y 张批量定价`)
                        ├─ 成本 costIncomplete = true → UI 显示「部分缺价」
                        └─ UI 单元格显示 .price-missing 徽章「无该批量定价」
```

## 5. Excel 导入导出流程

### 5.1 导出/模板流程

```
downloadPaperTemplate()
  └─ 内置 TEMPLATE_ROWS（9 张表，1:1 还原源 Excel）
      ├─ meta: 所属小组 / 总报价表 / 全称 / 简称 / 折扣系数 / 备注
      ├─ codeHeader: 代码 + 最大含出血面积 + 该纸档位表头
      ├─ codeRows: 规格数据
      └─ craftRows: 工艺名称 + 档位价格（无工艺则省略）
  └─ XLSX.utils.book_new() + book_append_sheet（sheet 名 = 简称）
  └─ XLSX.writeFile("KOKALabel1号报价表_日期.xlsx")

exportPaperExcel()
  └─ 遍历 PAPER_CONFIG → paperToSheetRows(paper)
      ├─ 规格档位 ∪ 工艺档位并集排序 = tierKeys（列宽对齐关键）
      ├─ 缺值留 ""（与源数据一致，不写 0）
      └─ 每个 paper 一个 sheet
```

### 5.2 导入流程

```
parsePaperExcel(arrayBuffer)
  ├─ XLSX.read → 遍历 SheetNames
  ├─ 表头区（前 8 行）标签匹配：所属小组/总报价表（跳过）、全称、简称、折扣系数
  │   └─ 缺全称/简称 → 跳过并报错；简称重复 → 跳过；折扣无效 → 默认 1
  ├─ 定位规格标题行：「代码」+「最大含出血面积」
  ├─ 档位表头：从第 3 列起，纯数字且 >0 → tierKeys
  ├─ 规格数据行：遇「工艺名称」行 break
  │   └─ code 重复/面积无效 → 跳过报错；空价格 → null（占位）
  ├─ 工艺区：定位「工艺名称」标题 → 逐行读价格（空 → null）
  ├─ paper id 复用：按简称匹配 DEFAULT_PAPER_CONFIG 保留原 id（工艺配置保持对应）
  └─ 返回 { papers, crafts, errors }

importPaperExcel(file)
  ├─ FileReader 读取 → parsePaperExcel
  ├─ PAPER_CONFIG = 导入数据；CRAFT_CONFIG = 默认 ∪ 导入工艺
  └─ rebuildPaperUI() 重建界面
```

### 5.3 解析容错规则汇总

| 场景 | 处理 |
|------|------|
| Sheet 为空 | 跳过 + 错误提示 |
| 缺全称/简称 | 跳过 + 错误提示 |
| 简称重复 | 跳过 + 错误提示 |
| 折扣系数无效（NaN/≤0） | 默认 1 + 错误提示 |
| 找不到规格标题行 | 跳过 + 错误提示 |
| 规格 code 重复 | 跳过该行 + 错误提示 |
| 面积无效（NaN/≤0/非整数） | 跳过该行 + 错误提示 |
| 价格空值 | → null（占位，UI 显示「无该批量定价」） |
| 价格非数字 | → null（占位）+ 错误提示 |
| 工艺重名 | 允许（用「名称@行号」去重，避免误丢） |
| 无任何可导入数据 | 抛错「没有可导入的1号报价表」 |

### 6.2 EPHEMERAL_KEYS 机制原理

```
const EPHEMERAL_KEYS = ["paperConfig", "craftConfig", "ropeConfig"];

启动时：EPHEMERAL_KEYS.forEach(k => localStorage.removeItem("tagPricing_" + k))
运行时：PAPER_CONFIG/ROPE_CONFIG/CRAFT_CONFIG 始终从 DEFAULT 初始化
写入时：saveToStorage() 中 if (EPHEMERAL_KEYS.includes(key)) return;

设计意图：测试阶段频繁更新云端报价数据，确保用户每次刷新拿到最新 DEFAULT，
避免旧缓存覆盖新数据。导入的本地数据仅当前会话有效。
正式版应移除此机制，改为正常持久化 + 云端同步。
```

## 9. 故障排查速查表

| 现象 | 原因 | 解决 |
|------|------|------|
| `403 Resource not accessible` | GitHub Token 无 repo 权限 | 重新生成 Classic PAT 勾选 repo |
| `Authentication error` | CF Token 无 Pages Edit 权限 | 重新生成 Token 选 `Cloudflare Pages · Edit` |
| `latest_deployment is null` | 首次未触发部署 | 推空 commit：`git commit --allow-empty -m trigger` |
| 部署一直 failed | 路径或构建配置错误 | 确认 `destination_dir = "/"`、根目录有 index.html |
| pages.dev 打不开 | DNS 污染/网络拦截 | 强制刷新 → 换手机流量 → 改 DNS 8.8.8.8 → 用 commit hash 子域名 |
| 页面样式丢失 | 缓存旧版本 | Ctrl+F5 或加 `?v=2` 查询参数 |
| 计算结果不对 | 价格键名不一致 | 检查 PAPER/ROPE/SHIPPING 配置键名 |
| Excel 库未加载 | CDN 被拦截 | 检查网络，确认 xlsx.0.20.1 CDN 可达 |
